Fix GHL Page Injection — 3 Issues

We have a Chrome extension (CF Extension) that injects AI-generated pages into GoHighLevel's page builder via Firebase. The Firebase write succeeds (HTTP 200) but the injected page never appears in GHL. Debug logs confirm three specific bugs to fix:

Bug 1 — Meta update endpoint is missing the location ID (CRITICAL)

The extension tries to PATCH/PUT GHL's backend after writing to Firebase, to update the page's download URL. All 6 attempts return 404 because none include the location ID.

The active GHL tab URL always contains the location ID:

https://app.gohighlevel.com/location/5jorVRA6PKGCAeTffHmA/page-builder/NaKUaWZ1OzCQYr3mx7PA

Fix: Extract locationId from the active tab URL and add these URL patterns to the meta update attempts (in addition to existing ones):

const locationId = tabUrl.match(/\/location\/([^/]+)\//)?.[1];

// Add these patterns to the metaUpdate attempt list:
`/locations/${locationId}/funnels/page/${pageId}`
`/funnels/page/${pageId}?locationId=${locationId}`
`/funnels/${funnelId}/page/${pageId}?locationId=${locationId}`

Try PATCH first, then PUT, for each new pattern.

Bug 2 — Injected elements are missing title and type fields

GHL native elements always contain title and type. The inject pipeline outputs elements without these fields. GHL uses type to determine which component to render — without it elements won't render.

Fix: In the element serialization/transform step, ensure every element node includes:

type — copy from the source element or default to "element"
title — copy from source or default to ""
Also remove _id from element nodes if present — it appears in the inject output but not in native GHL elements.

Bug 3 — Session storage is empty at inject time

The inject debug always shows:

Queued page (session storage): Nothing queued. Click 'Clone to GHL' in the app first.

This means the inject is running against stale/cached data. The "Clone to GHL" action in the web app is supposed to write the AI page data to session storage before the inject runs.

Fix:

Verify the "Clone to GHL" button correctly writes the page payload to sessionStorage with the expected key before triggering the extension inject
Add a guard in the inject entry point: if session storage is empty, show a user-facing error ("No page queued — click Clone to GHL first") and abort rather than silently injecting stale data
Context / What's Already Working:

Firebase Storage write: HTTP 200, token restored, public read works
Page data structure (flat format, sections contain elements directly): correct
secs count, hasElements, element hasMeta checks: all passing
The only things broken are the 3 bugs above
Do not change:

The flat format structure (elements stored in sections, not rows/cols/elems)
The Firebase write logic
The token patch logic (already working)
