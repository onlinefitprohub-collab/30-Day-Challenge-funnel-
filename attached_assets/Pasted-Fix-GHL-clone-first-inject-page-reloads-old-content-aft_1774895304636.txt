Fix GHL clone-first inject: page reloads old content after successful write

The inject returns ok=true with method=firebase-clone-first and replacedCount=3, but the GHL builder shows the old page after reload.

Root cause confirmed from debug output:

The roundtrip test proves that after any Firebase Storage POST write, Firebase generates a new downloadTokens value (tokenChanged: true). The roundtrip test fixes this by PATCHing the object metadata to restore the old token — and it works (patchToken: ok-format1, publicReadAfterPatch: 200).

The clone-first path in _cf_injectViaBuilderSave (inside background.js) does NOT do this patch. After writing npWritePayload to npUploadEp, the code immediately sets navigatedTo and returns. GHL then navigates to the new page URL but reads the Firebase file using the stale old-token URL → gets 403 → falls back to showing the template/old content.

Fix 1 — background.js, inside _cf_injectViaBuilderSave, clone-first path:

Find this block (it's inside the if (npFbMatch) block, after the template write):

var npWriteRes = await fetch(npUploadEp, {
  method:  'POST',
  headers: { 'Content-Type': 'application/json', 'Authorization': 'Firebase ' + idToken },
  body:    JSON.stringify(npWritePayload),
});
diag.approach2.cloneWriteStatus = npWriteRes.status;
if (npWriteRes.ok) {
  var newBuilderUrl = 'https://app.gohighlevel.com/location/' + ...

Immediately after if (npWriteRes.ok) { and BEFORE building newBuilderUrl, add a token-patch block that:

Parses the upload response JSON to get downloadTokens (the new token Firebase generated)
Extracts the old token from _npData.pageDataDownloadUrl using match(/[?&]token=([^&]+)/)
PATCHes https://firebasestorage.googleapis.com/v0/b/{npBucket}/o/{encodeURIComponent(npPath)} with body { metadata: { downloadTokens: oldToken } } and Authorization: Firebase {idToken} header
Logs cloneOldToken, cloneNewToken, cloneTokenChanged, clonePatchStatus, clonePatchToken to diag.approach2
Use var throughout (not const/let) since this runs inside executeScript.
