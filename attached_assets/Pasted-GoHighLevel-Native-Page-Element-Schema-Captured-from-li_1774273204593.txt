GoHighLevel Native Page Element Schema — Captured from live page builder

GHL pages are stored as a pageData object sent to Firebase via a changes POST request. The API call structure is:

{
  "pageData": { ...element tree... },
  "locationId": "your-location-id",
  "pageId": "your-page-id",
  "isPublished": false,
  "write": false
}
The element tree follows this exact hierarchy:
pageData.sections[] → rows (via child ID refs) → columns → elements

Section schema (the real format, captured from GHL):

{
  "id": "section-{randomId}",
  "metaData": {
    "id": "section-{randomId}",
    "_id": "section-{randomId}",
    "type": "section",
    "tagName": "c-section",
    "meta": "section",
    "title": "Section",
    "wrapper": {},
    "child": ["row-{id1}", "row-{id2}"],
    "class": {
      "borders": { "value": "noBorder" },
      "borderRadius": { "value": "radius0" }
    },
    "extra": {
      "visibility": { "value": { "hideMobile": false, "hideDesktop": false } },
      "desktopFontSize": { "value": 22, "unit": "px" },
      "mobileFontSize": { "value": "16", "unit": "px" },
      "typography": { "value": "var(--contentfont)" },
      "bgImage": {
        "value": {
          "options": "bgCover", "url": "", "svgCode": "",
          "opacity": ".3", "servingUrl": "", "placeholderBase64": "",
          "imageMeta": "", "showSvgToggle": false, "videoUrl": ""
        }
      }
    },
    "styles": {
      "backgroundColor": { "value": "var(--black)" },
      "paddingTop": { "value": 20, "unit": "px" },
      "paddingBottom": { "value": 60, "unit": "px" },
      "borderColor": { "value": "var(--color-fept2sjw21)" },
      "borderWidth": { "value": 5, "unit": "px" },
      "borderStyle": { "value": "solid" },
      "background": { "value": "none" }
    },
    "mobileStyles": {
      "paddingTop": { "value": 20, "unit": "px" },
      "paddingBottom": { "value": 30, "unit": "px" }
    }
  }
}
Key schema rules to follow exactly:

Every style value uses { "value": ..., "unit": "px" } format — never plain numbers or strings
IDs follow the pattern {type}-{randomAlphanumericId} — generate random IDs for each node
The structure is flat with ID references — sections reference rows by ID, rows reference columns by ID — they are NOT nested inside each other
All IDs must be unique across the entire page
CSS variables like var(--black), var(--contentfont), var(--color-xxx) are GHL's theme tokens — use these for theming
tagName values: sections = c-section, rows = c-row, columns = c-col, elements vary by type
meta mirrors type (e.g. "meta": "section", "meta": "row")
mobileStyles overrides styles on mobile — always include it even if empty {}
The element field inside metaData is a snapshot of the element's "original" state — duplicate the metaData object there
To write pages to GHL programmatically:
Use the GHL API with the user's API key:
POST https://services.leadconnectorhq.com/funnels/funnel/page/
or update via:
PUT https://services.leadconnectorhq.com/funnels/funnel/page/{pageId}
Body: the full { pageData, locationId, pageId, isPublished, write } structure above.
Auth header: Authorization: Bearer {ghl_api_key} + Version: 2021-07-28
