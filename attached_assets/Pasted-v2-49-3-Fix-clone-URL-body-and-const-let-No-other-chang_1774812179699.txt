Fix 1: Clone URL and request body

The real GHL clone endpoint (captured from live network traffic) is:

POST https://backend.leadconnectorhq.com/funnels/funnel/clone-funnel-step/

This URL requires the /funnel/ segment — previous versions incorrectly removed it or added a /phone-system/ prefix.

The request body requires these exact fields:

{
  "stepId": "<UUID of the funnel step containing the page>",
  "funnelId": "<funnelId>",
  "funnels": ["<funnelId>"],
  "locationId": "<locationId>",
  "userId": "<GHL user ID>"
}

stepId is not the same as pageId. A funnel has steps, each step has pages. To get stepId:

Call GET https://backend.leadconnectorhq.com/funnels/funnel/fetch/{funnelId} (already captured by bridge.js / already called by extension)
The response has data.steps[] — each step has id (UUID) and pages (array of page IDs)
Find the step whose pages array contains the current pageId
That step's id is the stepId to use
userId — read from GHL's Vuex store. The Vuex store is accessible via vueApp.config.globalProperties.$store where vueApp = document.querySelector('#app').__vue_app__. The userId is at store.state.auth.user.id or store.state.user.id — try both and use whichever is a non-empty string.

After the clone succeeds (201 response):

Response body: {"status":"ok","data":{"stepIds":["<newStepId>"]}}
Call GET /funnels/funnel/fetch/{funnelId} again, find the step with id = newStepId, get its pages[0] — that is the new page ID
Then proceed: look up new page Firebase path → write AI content → navigate builder to new page
