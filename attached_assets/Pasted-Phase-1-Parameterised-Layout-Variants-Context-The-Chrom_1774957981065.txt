Phase 1: Parameterised Layout Variants

Context

The Chrome extension now correctly writes pd.sections directly to Firebase. The page content is accurate. The next step is making the page STRUCTURE feel individually generated rather than templated. The AI currently generates a fixed skeleton for every page. This prompt makes it select from 5 layout variants per section type at generation time.

Step 1 — Confirm and codify the section type taxonomy

Read ghl-pagedata.ts and identify every section builder function. Map them to this taxonomy (add or rename if the code uses different names):

Section type key	Description
hero	Main headline, subheadline, CTA button, urgency line
social-proof-bar	Stars, trust bullets, "no credit card" line
whats-included	Feature/benefit list with checkmarks
how-it-works	Step-by-step or routine explanation
testimonials	Coach credentials or client results
faq	Questions and answers
final-cta	Closing call-to-action section
If any section type exists in the code but is not in this list, add it to the taxonomy. If any in the list doesn't exist, note it but do not create it yet.

Step 2 — Define 5 layout variants per section type

For each section type, implement 5 named layout variants in ghl-pagedata.ts. Each variant is a separate function (or switch case) that builds a different GHL element structure for the same content. All variants must use only valid GHL element types (c-row, c-column, c-heading, c-text, c-button, c-countdown, c-video, c-image, c-bullet-list).

Hero variants:

hero-centered — Single column, centered text, heading + subhead + CTA stacked, no right column
hero-two-col-video — Left column (text + CTA) + right column (video element)
hero-two-col-image — Left column (text + CTA) + right column (image placeholder)
hero-two-col-countdown — Left column (text + CTA) + right column (countdown timer)
hero-full-width — Full-width single column, large heading, subhead, CTA, urgency badge above heading
Social proof bar variants:

social-proof-stars-bullets — Stars rating + 3 trust bullet points in a row (current)
social-proof-centered-stat — Single large number/stat centered with descriptor
social-proof-three-stats — 3 columns each with a number + label
social-proof-single-quote — Single testimonial quote strip, centered
social-proof-horizontal-badges — Icon + text badges in a horizontal row
What's included variants:

included-three-col-checks — 3 columns with checkmark + short label (current)
included-two-col-bullets — 2 columns of bullet point lists
included-image-left-list — Image/photo left column + bullet list right column
included-single-col-numbered — Single column numbered list with descriptions
included-alternating-rows — Alternating left/right image + text rows (2–3 items)
How it works variants:

how-numbered-steps — 3 numbered steps in a row
how-single-col-list — Single column with step descriptions
how-two-col-image — Left image + right step list
how-icons-row — 3–4 icon + label + description columns
how-timeline — Vertical single column with connected steps
Testimonials variants:

testimonials-coach-left — Coach image left + credentials/bio right
testimonials-single-quote-large — Full-width large blockquote, centered
testimonials-two-col-cards — 2 testimonial cards side by side
testimonials-results-row — Before/after or result images in a row
testimonials-stats-strip — Key result numbers across a full-width strip
FAQ variants:

faq-single-col — Stacked Q&A pairs, single column (current)
faq-two-col — 2 columns of Q&A pairs
faq-image-left — Coach image pinned left, FAQ list right
faq-numbered — Numbered questions with styled answers
faq-with-inline-cta — FAQ list + CTA button at the bottom of the section
Final CTA variants:

cta-centered-color-bg — Centered heading + CTA button on solid color background (current)
cta-two-col-form — Headline left + button/form right
cta-with-countdown — Heading + countdown timer + CTA button
cta-dark-minimal — Dark background, minimal text, large CTA button
cta-social-proof-cta — Mini social proof line above heading + CTA
Step 3 — Add layout selection to AI generation

Find the prompt template that generates the page content (the Claude API call that produces headlines, body copy, FAQ answers, etc.). Add a layout selection instruction to the system or user prompt:

For each section you generate, also output a "layoutVariant" field selecting 
the most appropriate layout for the content from the available variants listed 
below. Base your selection on: the client's niche, the content length, 
whether visual proof elements (video/image/countdown) are appropriate, 
and variety — avoid using the same variant type repeatedly across sections.

Available variants per section type:
[insert the variant names from Step 2]

The AI output schema for each section should include:

{
  type: SectionType;
  layoutVariant: string; // e.g. "hero-centered", "faq-two-col"
  content: { ... } // existing content fields unchanged
}

Step 4 — Wire variants into ghl-pagedata.ts

Update each section builder in ghl-pagedata.ts to accept and use the layoutVariant field:

function buildHeroSection(content: HeroContent, layoutVariant: string): GhlSection {
  switch (layoutVariant) {
    case 'hero-centered': return buildHeroCentered(content);
    case 'hero-two-col-video': return buildHeroTwoColVideo(content);
    case 'hero-two-col-image': return buildHeroTwoColImage(content);
    case 'hero-two-col-countdown': return buildHeroTwoColCountdown(content);
    case 'hero-full-width': return buildHeroFullWidth(content);
    default: return buildHeroCentered(content); // safe fallback
  }
}

Every section type gets this same pattern. The default fallback should always be the simplest/safest variant for that section type.

Step 5 — Validation rule

If the AI returns a layoutVariant value that doesn't match any known variant for that section type, log a warning and fall back to the default. Do not crash — the page must always generate even if the AI returns an unexpected variant name.

Out of scope for Phase 1:

AI generating custom GHL JSON from scratch (Phase 2)
User being able to manually select or override the layout variant
Mobile-specific layout differences
Any changes to the Chrome extension or Firebase write logic
Done looks like:

Two users generating pages for different niches get visually distinct layouts
The debug output or generation log shows which layoutVariant was selected for each section
All 5 variants per section type are implemented and produce valid GHL element JSON
Fallback always works — no crashes on unknown variant names
